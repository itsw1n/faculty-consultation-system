These cases focus on the primary consultation workflow: sign in, publish availability, book, decide, cancel or complete, and verify participant visibility. Use separate Student and Faculty accounts for each dependent case, and use future, non-overlapping schedules.

Recommended test accounts: Student A, Student B, Faculty A, Faculty B, and Admin. Run cases 4–11 in order for a complete lifecycle. Use a separate consultation request for approval, rejection, cancellation, and completion so each transition is tested from a clean state. Fill in Actual result and Pass/Fail after testing; leave untested rows blank. Local demo accounts and setup steps are in [`../getting-started.md`](../getting-started.md#demo-accounts).
